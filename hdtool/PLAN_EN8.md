## 진행 상태 (2026-10-03, 영문 DOS2판 = illuk_EN 작업 트리, 미커밋)
**DOS2판 완료·검증됨**(S1–S8). 카트(S9)와 웹 도구(S10)는 아직. 한글판 결과물 md5 불변(ICITY.COM d95ea84f…, 청크 트리 efd821a5…).
- 구현: `mkdos2/icity.asm`(`-DEN8` 조건부), `mkdos2/patches_en8.py`, `mkdos2.py`(디스크 1 부트로 영문판 자동 식별, `manifest.json`의 `release`), `build.sh`·`make_dist.sh`(자동 `-DEN8`, 글꼴 `-`), `DIST_README_EN8.txt`, 시험 `mkdos2/test/en8/`.
- **1절 충돌의 결론이 바뀜(직접 확인)**: 게임 페이지 0의 003Bh–0054h는 **비어 있지 않다** — DOS2 페이지 0 이미지의 슬롯 전환 도우미(RDSLT 등 페이지 3 점프표가 호출)가 복사돼 있다.
  페이지 0에서 영문판 게임과 겹치지 않고 비는 곳은 007Ah–007Fh와 00F8h–00FFh뿐. 전환은 페이지 3 후크(E999h~)가 페이지 1·2를 바꾸고, 페이지 0에는
  `OUT (FFh),A / LD A,3 / OUT (FCh),A`(00F8h)와 `JP leave3`(007Ch)만 둔다. DOS2 쪽 페이지 0은 한글판처럼 007Ah–00FFh(FCB·명령줄 영역)를 쓴다.
  페이지 3은 E96Fh–E9FFh 안에 변수 9바이트, TBL 32바이트(E979h), 후크·leave3(E999h~E9D?)이 들어가고 DD30h–DD55h는 안 썼다.
- **게임 복사본 0080h–008Fh는 0으로 시작해야 한다**: 인터럽트 처리부가 (0088h)·(0089h)를 EI 직후 읽는다(E6B2h/E702h). DOS 명령줄 버퍼 찌꺼기가 들어오면 폭주(디스크 이미지의 파일 배치에 따라 나타남) → 영문판 모드에서 mk_page0이 16바이트를 0으로 만든다(한글판은 8바이트 그대로: md5 불변).
- 영문판 패치(위치 이동, 모두 원본 바이트 확인): L1 로더 0114h, L4 01D1h, K1 E224h(TBL E979h), INIT 1041h(로더 끝 0 영역 22바이트), K2 E5C3h, M1 file13 414Bh, M2 42F8h, M3 40AFh(변수 436Ah/43C3h). G1·G2 없음, P1–P6은 위 슬롯 페이지.
- **판정**: 영문판은 한자 ROM을 읽지 않는다(오프닝~디스크 2~엔딩 인트로, 포트 D8h–DBh 0회, G2 자리 ADFEh 미도달) → 글꼴 패치 불필요. 파일 14 크기 등 청크 표는 필요 없었다(`xfer`가 청크 경계를 넘어 읽으므로 경계는 정확하지 않아도 됨).
- 시험 결과(`mkdos2/test/en8/README.md`): 오프닝 읽기 232/232 일치(Nextor·ASCII DOS2, MIDI+FM·FM 전용), 일본어판 데이터 디스크 4장의 **27개 세이브 전부** 원본 플로피와 읽기 불일치 0(디스크 2–8 진입), MIDI 바이트 스트림 6000/6000 일치, 세이브 쓰기·재부팅 로드 확인, 빈(0) 유저 디스크 허용, MERGE=16 배포판 동작.
- **슬롯 96개 페이지 구현됨**(P1–P6, 한글판과 같은 파일 9 자리): 게임 쪽은 `secof·fixno·pg8·fixsel·page`(E9D3h–E9FBh)와 `newlist·cbk`(DD30h–DD55h; 27슬롯×220초 동안 게임이 안 쓰는 것 확인),
  키 처리(왼쪽/오른쪽, 조이스틱 1)는 DOS 쪽 서비스 51h(`ui_srv`) — `cbk`가 메뉴 반복마다 한 번 부르고 페이지가 바뀌면 5944h로 다시 그린다. 확장 슬롯 9번에 쓰기→페이지 2에서 로드 시험 통과, 전체 회귀 재통과.
- **카트(S9) 구현·검증됨**(`cart/cart.asm` `IFDEF EN8`, `cart/mkcart.py`가 영문판 자동 식별, 글꼴 인자 `-`): 부트 섹터 방식(디스크 1 섹터 0Bh–12h → 0100h, `PUSH 0100h / JP 0D46h`), 한자 ROM·글꼴 없음,
  페이지 0에서 영문판 게임이 덮는 자리(0055h~)의 저장 도우미는 E96Fh/EA00h로 이동, `subw/subr`는 꼬리를 공유해 0053h까지(RET가 0055h라서 0D46h에 덮여 A8이 BIOS 슬롯에 남는 문제가 있었음).
  결과(`cart/test/en8/README.md`): 오프닝 읽기 232/232(A16X), 27슬롯 두 매퍼 불일치 0·데이터 비교 bad=0, MIDI 일치, 저장·확장 슬롯 쓰기→재시작 로드 OK, 슬롯 목록 페이지 OK. 한글판 ROM md5 불변(A16X 45d25f08…, YAMA b94f9191…).
- 남은 것: 웹 도구(S10: 영문판 식별·DOS2/카트 만들기), 실기·MiSTer 확인, 엔딩을 실제 진행으로 끝까지.

## 1. 치명 충돌 (검토에서 발견, 직접 확인)
- **페이지 3 E947h–E96Eh**: DOS2 런처 변수 GSP·DTA·RSEC·RHL·RFN(E948h–E950h), UI(E951h–), TBL(E960h), 카트 GLYPHW(E947h, 글꼴·플래시 도우미 181바이트)가
  영문판 커널·파일 표 자리다. DOS2 스텁은 F37D마다 E948h~를 쓰므로 **파일 표를 깨뜨려 엉뚱한 섹터를 읽게 된다**.
- **페이지 0**: DOS2 스텁 0090h–00FFh, INP 0055h–007Fh, UI_FIXSEL 00F6h, 카트 erase64·p128·possec·slotsec·chsec·rdhdr(0056h–00F8h)가 영문판 코드·글꼴 폭 표와 겹친다.
  영문판에 남는 페이지 0은 003Bh–0054h(26), 007Ah–007Fh, 00F8h–00FFh뿐.
- 결론: "겹치면 옮긴다"가 아니라 **스텁·도우미 배치 재설계가 별도 단계**(S2)이고, 로더 패치(S4)보다 먼저다.

## 2. 단계
**S1. 원본 실행 기록과 빈 곳 측정** (openMSX 표준 `Panasonic_FS-A1GT`, 플로피 원본, FM·MIDI)
- 스타트→디스크 2 오프닝, 세이브 로드→디스크 4·6, 엔딩 인트로(모드 2 강제 진입, `fdd/test/mode2.tcl` 방식, 영문판 주소로).
- 기록: F37D 호출, 한자 ROM 포트 D8h–DBh(**G2 루틴이 실제로 불리는지**), 메모리 쓰기 감시(`phase0/watchfree` 방식)로
  **E96Fh–E9FFh, DD30h–DD91h, 페이지 0 빈 곳, FB30h–FCAFh 바깥 시스템 영역**이 게임 중 쓰이는지.
- 판정: 디스크 2–8 파일 찾기(F5의 "INF 고정 / (C000h)=디스크 번호" 추정 확인), 섹터 284–299를 누가 읽는지, 변수 주소(5EC0h·5EC3h·5EC5h·메뉴 IX)가 같은지.

**S2. 배치 재설계** (S1의 빈 곳 결과로)
- DOS2: 스텁·변수·TBL을 새 자리로(후보 E96Fh–E9FFh 145바이트: 글리프 래퍼를 빼면 약 142바이트, 페이지 0에는 26바이트 트램펄린만).
  DOS2 페이지 3 사본 위에 영문판 DD00h·DF7Eh가 오는지 대상 구성(MSX-DOS2, Nextor, SD 드라이버)별 HIMEM 기록과 검사 추가.
- 카트: 플래시 도우미·글리프 코드 약 130+181바이트를 나눠서 새 자리로(후보 E96Fh–E9FFh, DD30h–DD91h). 인터럽트 스택(DD92h 아래)과 0D46h·EI 순서 확인.
- 한글판 배치는 그대로 둔다(판별 조건부 빌드) → 한글판 결과물 md5 불변.

**S3. 판 식별과 청크**
- 디스크마다 식별, **8장이 모두 같은 판일 때만 진행**: EN8 = 디스크 1 부트 +53h `21 00 08 11 0B 00` 그리고 디스크 2–8 섹터 1–13 전부 0. EN6 = 부트에 `11 99 05 26 07`(지원 안 함, 안내). 한글·일본어는 파일 7 바이트로 구분.
- 청크: E941h 표(로더 0D18h)로 가짜 섹터 11 표를 만들어 기존 분할 코드에 넣는다. 디스크 3·4·5 파일 14 크기, 디스크 2–8 INF (0Eh,05), 디스크 1 섹터 284–297 직접 읽기를 반영.
  **고정 범위 0–18(로더 포함)은 디스크 1에만**. `expected` 표는 판별로.
- 카트는 섹터 단위라 청크 표가 필요 없음(로더 처리만).

**S4. 로더·커널 패치 위치 맞추기** (L1 L4 K1 INIT K2) — 다시 쓰기가 아니라 피연산자 와일드카드 패턴으로 위치 이동. INIT 코드는 로더 끝 빈 곳 1041h–10FFh(191바이트, 0).
런처·카트의 FRAY 로드를 EN8에서는 "섹터 11–18 → 0100h, 8바이트 → 0080h, 0D46h 호출 뒤 0100h"로. FRAY 디렉터리 항목은 쓰지 않는다(F1의 조용한 오류 방지).

**S5. MIDI 패치 위치 맞추기** (M1 14Bh, M2 2F8h, M3 재확인, 내부 주소 갱신). 곡 섹터식(0152h + 인덱스 − 0250h)을 S1 MIDI 기록으로 확인.

**S6. 글꼴** — S1에서 G2 루틴이 불리면: 일본 한자 ROM이 있는 기계(표준 GT/ST)에서는 패치 없이 원본대로(G1·G2 생략), 글꼴 파일을 필수로 요구하지 않게(웹 도구 core.js 320행 조건 분기).
안 불리면 생략. 키티야 님 글꼴은 한글판 전용.

**S7. 기타 한글판 가정 끄기** — `blank_armi`(EN8은 588h–599h, 머리 다름: 빼거나 EN8용 확인값), `buildFdd`의 FRAY 패치(EN8 플로피판은 이번 범위 밖), `mkdos2.find_disk` 파일 이름.

**S8. DOS2 빌드·시험** — FM 125·MIDI 500 읽기를 S1 원본 기록과 대조 불일치 0(패치 자리 제외), 세이브 8슬롯·확장 슬롯 저장·재시작, MSX-DOS2와 Nextor 둘 다.

**S9. 카트 빌드·시험** — 두 매퍼, 같은 대조, 디스크 4·6(2MB 넘는 뱅크), 확장 슬롯 뒤, save2.tcl, 엔딩 인트로.

**S10. 웹 도구** — 판 자동 식별, EN8 패치·표, 네 브랜치 반영. 크레딧.

## 3. 검수 기준
- 출력이 원본 플로피 실행과 같은 섹터 데이터를 받는다(불일치 0, 패치 자리 제외).
- 긴 진행 중 쓰기 감시: E941h–E96Eh, 0055h–0079h, 0090h–00F7h, FB30h–FCAFh, DD00h–DD2Fh, DF7Eh–DFFEh, 새로 옮긴 영역에 우리 코드가 쓰지 않음.
- 한글판 회귀: 결과물 md5 불변(A16X 45d25f08…, YAMA b94f9191…), 웹 시험 `test_node.js`·`test_cart.js` 통과.
