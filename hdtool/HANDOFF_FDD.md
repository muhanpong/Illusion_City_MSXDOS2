# 원본 플로피(FDD)판 작업 인수인계 — 2026-09-30

다음 작업: **원본 플로피판(디스크 8장 + 유저 디스크)을 다시 본다.** 이 문서는 지금까지 세 판(Nextor 에뮬레이션, DOS2, 카트리지)을
만들며 확인한 게임 구조와 도구를 한곳에 모은 것이다. 새 세션은 여기서 시작하고, 먼저 **1절의 목적을 사용자에게 확인**할 것.

## 1. 목적 (사용자 확인 필요)
사용자 지시는 "원본 fdd를 한번 봅시다"뿐이다. 후보:
- (a) 원본 디스크 그대로 **분석**(부팅·디스크 교체·세이브·유저 디스크 만들기 흐름).
- (b) **플로피용 개선판**: 다른 판에 넣은 것 중 플로피에 옮길 수 있는 것(한글 글꼴 없이도 되는지, 세이브 슬롯 확장 등, 3절).
- (c) 원본과 개선판의 **차이 검증**(같은 진행에서 같은 요청·같은 화면).

## 3. 게임 구조 (확인된 사실)
**디스크:** 720KB(1440섹터) FAT12. 섹터 0 라벨 +3 `IPROJ0n`(디스크 n), 유저 디스크는 라벨만 다른 사본(`USERDISK`로 만든 판도 있음).
디스크 1 섹터 11 = 파일 표(시작 섹터, 섹터 수) 15개: 파일 7 = 섹터 82부터 63섹터(메모리 0100h–7EFFh), 파일 9 = 156부터 36섹터(엔진, 4000h),
파일 13 = MIDI 모듈. `FRAY.DOS`(0CA2h바이트, 섹터 14–20)가 로더.
- 원본 이미지 판본: zip의 디스크 1 섹터 66h(파일 7 2AB9h 글꼴 루틴)는 한자 ROM 포트 **D9h/DBh**. 저장소 밖 `I-CITY_K.DSK`는 이것이
  **59h/5Bh**로 바뀐 판(GT에서는 글자가 흰 사각형). 나머지 섹터는 같다.

**부팅(원본):** 부트 섹터 C01E(CF=1) → FCB로 FRAY.DOS를 0100h에 → 0080h–0087h = `00 00 00 98 98 23 F3 00`, SP=FAF8h, `JP 0100`.
DOS1 환경(페이지 0 진입점, DD92h–DF7Dh 루틴) 위에서 돈다. GT(DOS2 커널)는 DOS1 부트 섹터를 보면 DOS1 모드로 다시 부팅한다.
**디스크 I/O:** 전부 F37D. 1Ah(DTA), 2Fh(절대 읽기: DE=섹터, H=개수, L=드라이브), 30h(쓰기: 세이브만). 섹터 0 읽기 = 디스크 확인,
원하는 디스크 번호는 (5EC0h)(파일 9 변수, 0–7 = 디스크 1–8, 10 = 유저 디스크), 확인 루틴 5B48h. 원본은 이때 "디스크를 넣으라"고 기다린다.

**세이브:** 로드 메뉴 = 매체(5EC3h): 1 Quick, 2 SRAM(GT 내장 추정, 페이지 3 E00Ch/E009h), 3 디스크 1, 4 유저 디스크.
디스크 슬롯 8개: 섹터 0578h+2n(2섹터 1KB), 목록 5944h(8줄), 선택 (5EC5h), 읽기 5A4Dh / 쓰기 5A76h(`LD HL,0578h / ADD HL,DE ×2 /
LD DE,F400h / LD C,30h / LD B,2`), 유효 판정 F7F8h 6바이트 서명, F400h→C000h 3FAh바이트. 메뉴 선택 루틴 308Ah는 HL 콜백을 매 반복 부른다.
**측정: 게임이 유저 디스크에서 읽는 섹터는 0과 0578h–0587h뿐**(여러 판 실행 기록). 디스크 1–8은 빈 섹터가 31–94개로 거의 꽉 참.

**메모리:** 게임 페이지 3: E000h–E946h 게임 코드(7D62h가 DF7Eh–EF7Fh를 채움), EA00h DTA, **E947h–E9FFh 게임이 안 씀**.
DOS1 디스크 드라이버 코드 EF80h–F139h(원본에서 매 읽기 실행). DOS1 커널 변수 중 게임이 안 쓰는 곳: F13Ah–F169h, F176h–F276h,
F27Fh–F322h, F325h–F340h, F345h–F367h(게임이 쓰는 곳: F16Ah–F16Eh, F175h, F277h, F27Eh, F323h/F324h). 페이지 0: 게임은 0087h–0089h,
008Fh만 쓰고, 시작 때 페이지 0 전체를 자기 세그먼트들에 복사한다(PC 8121h). H.KEYI는 게임이 `JP E6C0`. 게임은 CHGCPU로 R800을 켠다.
**글꼴:** 게임의 유일한 한자 ROM 접근 = 파일 7 2AB9h(28바이트, 글리프 32바이트 → D500h). 패치 G1로 가로챌 수 있음(HL=D520h, BC=00D9h 계약).
**MIDI:** 파일 13 모듈(세그먼트 10h), 플레이어 12h, 곡은 디스크 1에서 필요할 때 읽음(DOS2판 패치 K2, M1–M3). 음원 선택은 시작 메뉴 한 번.

**다른 판에 넣은 게임 패치(참고):** G1(글꼴), P1–P6(슬롯 목록 페이지: 590Ah 콜백, 5957h 표시 번호, 5910h 선택, 58E3h 목록 열기,
5A66h/5A8Fh 섹터 — 9번 이후 0600h+2n). DOS2판 L1/L4/K1/INIT/K2/M1–M3(매퍼·MIDI). 목록 다시 그리기 ~5초(원본 출력 속도).

## 4. 플로피판에 옮길 때 생각할 점
- 슬롯 확장: 지금의 0600h+ 섹터는 720KB 디스크 밖이라 플로피에선 안 된다. 유저 디스크는 0과 슬롯 섹터만 읽히므로 나머지
  약 1400섹터를 슬롯으로 쓰면 수백 개가 가능해 보인다(**미확인**: 유저 디스크를 게임이 어떻게 만드는지, 다른 섹터를 쓰는 기능이 있는지).
  디스크 1 슬롯은 빈 곳이 없어 8개 그대로.
- 글꼴: 표준(일본) GT에는 한글 한자 ROM이 없다. 플로피 공간이 없어 글꼴(256KB)을 디스크에 넣기 어렵다 → 한글 ROM 필요 전제이거나 별도 방법.
- 패치는 파일 7/9 안(디스크 1)이라 디스크 이미지만 고치면 된다. 새 코드 자리는 E947h–E9FFh 등 3절의 빈 곳(플로피판은 DOS1 커널이
  살아 있으므로 커널 변수 자리는 쓰면 안 됨: 카트리지판과 다르다).

## 5. 도구와 시험 방법
- openMSX 21, 기계 `kittya`(FS-A1GT + 한글 한자 ROM, `~/.openMSX/share/machines/kittya.xml`), 표준 GT `Panasonic_FS-A1GT`.
  헤드리스: `SDL_VIDEODRIVER=offscreen` + `set renderer SDLGL-PP`(스크린샷 가능) / `set renderer none`. `set firmwareswitch off`.
- 원본 플로피 진행: 디스크 이미지를 `diska`로 넣고, F37D 2Fh DE=0 요청 때 (5EC0)을 보고 해당 디스크로 바꿔 끼우는 Tcl(`hdtool/phase0/e8f5/force_e8f5.tcl`의 `on_bdos`).
- 키 입력: 메뉴는 커서가 뜬 뒤에만 받는다. 시간표 대신 메뉴 루틴(3AEFh·308Ah) 진입 때의 IX(8338h 음원, 836Eh 메인, 5C19h 매체,
  5C86h 슬롯 목록)와 (34D2h 현재 항목)으로 누르는 방식이 안정적(`hdtool/mkdos2/test/slots.tcl`). 키 행 8: 스페이스 01h, 아래 40h, 오른쪽 80h, 왼쪽 10h.
- 역어셈블: `objdump -D -b binary -m z80 --adjust-vma=<주소> file.bin`(파일 7 = 0100h, 파일 9 = 4000h).
- 섹터 검증: `hdtool/cart/test/verify.tcl`(매 2Fh 읽기를 디스크 이미지와 비교), 세이브: `save2.tcl`(카트리지), `mkdos2/test/slots.tcl`(DOS2).
- 데이터: 저장소 밖 `/home/sysop/data/Illucity_HD/`의 `illucity_K.zip`(원본 8장), `userdisk.DSK`, `KANJI.rom`(한글 한자 ROM = 글꼴).
