# 플로피판: 한글 한자 ROM 없이 (디스크 1 패치)

`mkfdd.py <원본 디스크 8장 폴더> <KANJI.rom> <출력 폴더>` → 디스크 1만 바뀐 `D1.dsk`–`D8.dsk`. 유저 디스크는 그대로 쓴다.
FM·MIDI 두 모드 모두, 한글 롬이 없는 표준 FS-A1GT에서 게임 글자가 디스크 1의 글꼴로 나온다.

## 구성
- **글꼴**: 게임이 찍을 수 있는 글리프 1395개(`hdtool/phase0/glyphscan`, 대사·메뉴·오프닝·엔딩 전체를 정적으로 스캔)를 40개씩
  블록으로 ZX0 압축(35블록, 17406바이트). 디스크 1 섹터 550h부터 38섹터(29 + 9)에 둔다. 550h–577h는 게임이 읽지 않는 빈 곳
  (디스크 1 INF 목록의 마지막 데이터가 546h+8, 578h부터 세이브 슬롯).
- **메모리**: 파일 13의 섹터 캐시 끝을 인덱스 3D0h로 고정(4113h MIDI 경로, 4245h FM 경로. 원래는 매퍼 크기×32 = 400h).
  세그먼트 1Fh 전체와 1Eh 오프셋 2000h–3FFFh가 비고, 여기에 글꼴을 둔다.
  - MIDI: 곡 캐시가 인덱스 3C9h까지 차서 섹터 캐시는 3CAh–3CFh(6섹터, 원래 54섹터). **끝이 시작보다 작으면 파일 13이 크기를 최대치
    5A0h로 잡아 글꼴을 덮어쓴다**(처음 3C8h로 했을 때 실제로 발생).
  - FM: 섹터 캐시 0250h–03CFh(384섹터, 원래 432).
- **부팅**(FRAY.DOS 끝에 붙인 `init`, 0154h `JP E000h` 대신): 주 매퍼가 32세그먼트 이상이면 1Fh와 1Eh에 글꼴을 읽고 FLAG=1.
  아니면(256KB 기계) 원래대로 한자 ROM을 쓴다.
- **글자 읽기**: 파일 7 2AB9h(게임의 한자 ROM 읽기)와 파일 14 ADFEh(엔딩의 사본, 버퍼 86BCh)를 page 3 스텁(E947h–E9C4h)으로.
  스텁이 커널 E030h로 1Fh를 page 2에 올려 8000h를 부르고(색인: 상위 5비트 버킷 + CPIR, 블록이 바뀌면 BUF로 풀기, 1Eh 블록은
  page 1에 잠깐 올림), E033h 뒤 32바이트를 목적지로 복사한다. 목록에 없는 글자는 빈칸.
- FRAY.DOS는 215바이트 늘고(7섹터 안), 디렉터리의 크기도 고친다. 패치는 모두 원래 바이트를 확인한 뒤 쓴다.

## 검증 (openMSX, 2026-09-30)
- 표준 `Panasonic_FS-A1GT`(한글 롬 없음), 원본 디스크 교체 자동화(`run.tcl` 방식): MIDI 10가지(오프닝, 스타트, 유저 디스크
  세이브 8개) + FM 3가지, 각 700–900초. 요청된 글리프 **92,000여 개를 모두 KANJI.rom과 비교해 불일치 0**, 부팅 뒤 한자 ROM
  포트(D8h–DBh) 쓰기 0, FLAG=1. 화면의 메뉴·대사가 한글로 나온다.
- MIDI 섹터 캐시 크기 6(시작 3CAh) 확인.
- 미확인: 엔딩(파일 14 사본 g14는 한 번도 불리지 않음), 디스크 3–6·8 구간(자동 조작이 디스크 7로만 감), 실기.
