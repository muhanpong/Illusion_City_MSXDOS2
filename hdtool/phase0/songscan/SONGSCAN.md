# MIDI 곡 사용처 정적 스캔 (2026-09-30)

목적: 플로피판 MIDI 모드에서 곡 캐시(디스크 1 섹터 0152h–02C8h, 375섹터, 세그먼트 12h 뒷부분–1Eh)를 줄여 글꼴(FONT.BIN) 자리를
만들기 위해, **어느 디스크에서 어느 곡이 재생될 수 있는지**를 실행 없이 게임 데이터에서 뽑는다. 도구: `songscan.py <D1..D8.dsk 폴더>`,
결과: `result.txt`.

## 1. 곡 번호가 정해지는 경로 (openMSX 추적으로 확인)
- 곡 번호 변수 CA48h(1-based, 0 = 없음)는 파일 7 5050h만 쓴다. 재생은 파일 7 02E4h가 CA48h−1을 모듈 4012h로 넘긴다(0398h 래퍼).
  둘째 채널 CA49h(505Dh, 02F9h)도 같은 곡 표를 쓴다.
- 5050h/505Dh를 부르는 곳과 번호의 출처:
  | 출처 | 코드 | 데이터 |
  |---|---|---|
  | 장면 진입 | 파일 7 4D6Fh: `(ix+24)`→5050h, `(ix+25)`→505Dh | 각 디스크 파일 6 `INF`: 20h 헤더(4h 전체 길이, 6h부터 구간 길이 5개) 뒤 26바이트 장면 기록(이름 3, 청크 (섹터 u16, 수 u8)×7, +24 BGM, +25 둘째 채널) |
  | 이벤트 시작 | 파일 9 7842h: F7EDh='B'면 F7EEh+1→5050h | 장면 청크 `EVT`(20h 헤더: 4h 전체, 6h부터 구간 길이 5개, 15h 스크립트 수 N). 4번째 구간 = N개 u16 오프셋 표 + 문자 명령 스크립트(해석기 파일 9 7614h, 명령 표 7BBCh: 글자 [+개수] +인자, 'E'/'e' 끝). `B n` 이 F7EDh–F7EEh로 복사됨(n = 0-based) |
  | 바이트코드 | 파일 9 8009h(명령 0Fh): `(ix+1)`→5050h | EVT 5번째 구간, 디스크 1 파일 11: `c8 0f c1 n`(n 1-based). 상수 인자만 인식 |
  | 디스크 1 프로그램 | 파일 5(타이틀·오프닝) 981Ch, 파일 14(엔딩) 9C55h | `ld a,n` 상수 |
  | 엔진 | 파일 9 47F8h: D8F5h=1 | 곡 0 |
- 곡 표(파일 4가 CD00h에 만듦, 37항목: 시작 섹터 u16, 섹터 수 u8): 12·19번은 비어 있음(길이 0). 합계 383섹터.
- 스캔 검증: 명령 해석 실패 0(디스크 2–8, 명령 5592개). 실행 기록과 대조 — 디스크 1: 35, 27, 28(상수), 디스크 2: 9(EVT-B), 10(INF),
  디스크 5·7: 0, 디스크 7: 7(INF) — 모두 표에 있음.

## 3. 한계
- 바이트코드 0Fh 명령의 인자가 변수인 경우는 못 잡는다(스캔한 범위에서는 모두 상수 `c1 01` = 곡 0).
- 디스크 1은 INF 장면 기록이 없어 파일 5·14의 상수와 파일 11의 바이트코드만 봤다. 파일 4·10(음원 메뉴 등)에는 곡 재생 코드가 없었다.
- 둘째 채널(+25)이 실제로 언제 울리는지는 확인하지 않았다(값 32–35 = 곡 31–34).
