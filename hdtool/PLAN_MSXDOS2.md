# ASCII MSX-DOS2 구현 계획 (branch: msxdos2)

목표: FS-A1GT 내장 ASCII MSX-DOS2 + 실기 저장장치 **MMC/SD V4(주력)** 또는 MegaFlashROM SCC+ SD에서
`ICITY.COM` 실행 → 게임이 HD의 개별 파일(`Dn_ssss.DAT`)에서 데이터를 읽고, 세이브를 파일로 기록.
Nextor와 디스크 에뮬레이션은 쓰지 않는다.

## 1. 데이터를 파일로 자르는 방법

### 1-1. 절대 섹터 참조 출처 (현재 확인분)
| 출처 | 위치 | 형식 |
|---|---|---|
| 파일 테이블 | 각 디스크 섹터 11 | (시작 섹터, 섹터 수) 바이트 쌍, 번호로 접근 |
| INF 카탈로그 | 파일 6 (디스크 2–8) | 이름 3자 + (시작 u16, 길이 u8)×7 레코드, 뒤에 이름 없는 표들. 디스크당 레코드 14–31개, 서로 다른 구간 54–85개 |
| INF 뒤쪽 표 | 파일 6 후반부 | 헤더(+4..)의 오프셋이 가리키는 구간 목록. 형식 해독 필요 |
| 엔진 내부 표 | 디스크1 파일 7 등 (예: B7D5 표 → 섹터 0x539–0x54E) | 코드가 들고 있는 섹터 번호 |
| 시나리오 | 파일 14 (scn) | 이벤트 그림/음악 참조 가능성. 조사 필요 |
| 고정 섹터 | 섹터 0(디스크 확인), 0x578+2n(세이브) | 코드 상수 |

### 1-2. 정확성 보장 원칙
- 참조 조사를 아무리 해도 빠지는 것이 있을 수 있다. 그래서 **런타임 해석기를 "구간 표" 방식**으로 만든다.
- 디스크마다 발견한 모든 구간의 시작과 끝을 분할점으로 삼아 서로 겹치지 않는 조각을 만든다.
- 어떤 구간에도 속하지 않지만 0이 아닌 섹터도 조각으로 만든다. 디스크의 사용 데이터가 빠짐없이 파일에 들어간다.
- 요청(디스크, 섹터, 개수)은 표에서 조각을 찾아 "파일 + 오프셋"으로 바꾸고, 조각 경계를 넘으면 나눠 읽는다.
- 그 결과 참조 조사가 불완전해도 동작은 정확하다. 조사 품질은 조각 경계가 얼마나 자연스러운지에만 영향을 준다.

### 1-3. 파일 배치
- 이름: `D<n>_<시작섹터 4자리 hex>.DAT` (예: `D2_02BB.DAT`). 8.3 규칙 충족.
- 디렉터리: `\ICITY\D1\ … \ICITY\D8\`, 세이브는 `\ICITY\SAVE\` (디스크1 슬롯 8개, 유저 디스크 슬롯 8개).
  디렉터리 하나에 파일이 많으면 DOS2 열기가 느려지므로 디스크별로 나눈다.
- 예상 규모: 디스크당 수십–200개, 전체 1000–1500개(조사 후 확정).
- 구간 표(디스크별 시작 섹터 목록)는 런처 안에 넣는다. 파일명은 시작 섹터로 계산되므로 따로 저장하지 않는다.

## 2. 실행 구조: 두 환경 전환

게임은 C000–FFFF와 page 0의 0x80–0x8F를 직접 쓰므로 DOS2와 같은 메모리에서 공존할 수 없다.
DOS2 환경과 게임 환경을 매퍼 세그먼트로 분리하고, 매퍼 레지스터(FC–FF)만 바꿔 오간다.

| | DOS2 환경 | 게임 환경 |
|---|---|---|
| page 0–3 | DOS2 TPA 세그먼트 | 런처가 DOS2 매퍼 지원 루틴으로 할당한 세그먼트 |
| page 3 | DOS2 시스템·드라이버 작업영역 | 게임 데이터 + BIOS 영역(F380–FFFF) 사본 |
| 인터럽트 | BIOS/DOS2 처리 | 게임 자체 0038 처리기 |
| F37D | DOS2 커널 | 전환 코드로 연결 |

전환 코드(page 0의 0x90 부근, 두 환경 같은 주소에 동일하게 복사) 동작:
1. DI, 게임 환경 매퍼 값과 SP 저장 → DOS2 환경으로 전환, DOS2 쪽 스택 사용.
2. 요청을 구간 표로 해석 → 조각 파일 열기(마지막 핸들 재사용) → `_SEEK` → `_READ`/`_WRITE`.
3. 바운스 버퍼(전용 세그먼트, page 2)를 거쳐 16KB 단위로 처리.
4. 게임 환경으로 돌아와 바운스 버퍼를 실제 목적지로 복사(page 3 목적지 포함).
5. 섹터 0 읽기는 파일 대신 게임이 원하는 디스크(0x5EC0)의 라벨을 합성해 돌려준다. 디스크 교체 화면이 사라진다.
6. 섹터 0x578+ 읽기/쓰기는 SAVE 디렉터리 파일로 보낸다.

세그먼트 변환: 커널 E25B(매퍼 전환 단일 지점, 논리 0–18 사용)를 패치해 할당받은 물리 세그먼트로 바꾼다.
엔진 파일 안 직접 매퍼 포트 쓰기 후보(파일 5, 7, 9 등)도 확인 후 같은 표로 패치한다.

## 3. 단계

### 0단계: 조사
1. INF 전체 형식 해독(뒤쪽 표 포함), 파일 14 시나리오의 섹터 참조 여부, 엔진 코드 내 섹터 상수 표 수집.
2. 원본을 openMSX에서 장시간 실행하며 모든 F37D 요청(디스크, 섹터, 개수, 호출 주소) 기록. 정적 목록에 없는 요청을 찾아 1번을 보완.
3. 게임이 쓰는 논리 세그먼트 최댓값, 직접 매퍼 포트 쓰기 전부 확인.
4. ASCII DOS2 + IDE(ide250) 환경에서 TPA 상한, 빈 세그먼트 수, page 3 사용 범위 측정. 필요량 약 19(게임) + 1(바운스) + 여유.

### 1단계: 변환 도구 `mkdos2.py`
- 입력: 원본 디스크 8장 + 유저 디스크. 출력: 조각 파일, 디렉터리 구조, 구간 표(런처 포함용 include 파일).
- 검증 기능: 조각을 다시 이어 붙여 원본 사용 섹터와 바이트 단위 일치 확인.

### 2단계: 런처 `ICITY.COM` (sjasmplus)
1. DOS2 버전과 매퍼 지원 확인, 세그먼트 할당. 부족하면 안내 후 종료.
2. 게임 환경 구성: page 3에 F380–FFFF 사본, F37D 연결, 전환 코드 두 환경에 복사.
3. FRAY.DOS를 `\ICITY\D1\`에서 읽어 게임 환경 0x100에 올리고 패치 후 시작.

### 3단계: 세그먼트 변환과 매퍼 검사 통과 처리

### 4단계: 인터럽트·장치 상태
- DOS2 환경에 머무는 동안 게임 음악은 멈춤(원본도 디스크 접근 중 끊김). 필요하면 DOS2 쪽 0038을 최소 처리기로 교체.
- VDP R15, PSG, CPU 모드(R800), MIDI 상태 유지 확인.

### 5단계: 검증
| 항목 | 방법 |
|---|---|
| 조각 파일 무결성 | 변환 도구 자체 검사(원본과 바이트 일치) |
| 요청별 데이터 동일성 | 원본 실행과 DOS2판 실행의 요청 기록 + 목적지 메모리 해시 비교 |
| DOS2 환경 보호 | 게임 중 DOS2 세그먼트 쓰기 감시(openMSX watchpoint) |
| 진행 | 오프닝, 스타트, 디스크 2–8 구간(세이브 데이터로 점프), 엔딩 |
| 세이브 | 두 종류 슬롯 저장 → 리셋 → 로드 |
| 음원 | FM, MIDI |
| 실기 | FS-A1GT + 실제 HD에서 반복 |

테스트 환경:
- 런처는 표준 DOS2 기능 호출과 매퍼 지원 루틴(EXTBIO)만 쓴다. 그래서 ASCII DOS2와 Nextor DOS2 모드 모두에서 동작해야 한다.
- openMSX에는 MMC/SD V4가 없으므로 두 환경으로 대신 검증한다.
  - `kittya` + `ide` 확장(Sunrise IDE BIOS 2.50): ASCII DOS2 커널 + 외부 디스크 드라이버 구조. MMC/SD V4와 같은 형태.
  - `kittya` + `MegaFlashROM_SCC+_SD` 확장: 실기 MFRSD와 같은 환경(Nextor 커널).
- 두 환경에서 TPA 상한과 빈 세그먼트 수가 다르므로 가장 나쁜 쪽에 맞춘다.
- 최종 확인은 실기 FS-A1GT + MMC/SD V4.

## 4. 위험
- 파티션 크기: MMC/SD V4는 FAT16 확장 지원이라 문제없음. 파일 수는 디스크별 디렉터리로 분산.
- MMC/SD V4 드라이버가 page 3 작업영역과 세그먼트를 얼마나 쓰는지 실기에서만 확인 가능 → 런처가 시작할 때 TPA 상한과 빈 세그먼트 수를 화면에 표시하게 해서 실기 측정값을 받는다.
- 파일 열기 속도: 요청마다 열면 느릴 수 있음 → 디스크별 디렉터리 + 핸들 재사용. 필요하면 디스크당 파일 수를 줄이도록 인접 조각 병합 옵션.
- 세그먼트 변환 누락 시 DOS2 메모리 파손 → 0단계 3번과 watchpoint.
- DOS2 호출 중 EI → DOS2 환경 page 0은 반드시 DOS2 것이어야 함(설계 반영).

## 5. 첫 작업
0단계 1–2번: INF 형식 해독과 원본 장시간 요청 기록 스크립트. 결과로 디스크별 구간 목록 초안을 만든다.
