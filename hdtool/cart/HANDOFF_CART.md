# 카트리지판(Yamanooto / ASCII16-X) 인수인계 — 2026-09-30 (3차: 4MB 압축판)

목표: **카트리지만 꽂으면 부팅되는** 환영도시(ILLUSION CITY) ROM. 대상 매퍼 두 가지(사용자가 실기 둘 다 보유).
DOS2판(`hdtool/mkdos2`, 배포 zip, 웹앱)은 완료 상태이며 이 작업과 별개다.

## 0. 현재 상태
(영문 8장판 카트는 `cart.asm`의 `IFDEF EN8`와 `mkcart.py` 자동 식별로 같은 도구에서 나온다: `test/en8/README.md`, `PLAN_EN8.md`. 한글판 ROM은 그대로.)

- **ROM은 4MB**(4MB 이상 플래시면 됨). **ASCII16-X 파일만 오프셋 0010h(4010h–4017h)에 `"ASCII16X"` 서명**: openMSX(guessRomType)와
  MiSTer 코어(`mapper_detect.sv`, OSD 매퍼 auto)가 크기와 상관없이 ASCII16-X(플래시)로 고른다. 전에는 코어가 4MB 초과 파일만
  플래시로 인식해(`memory_upload.sv` rom_big, OSD에서 ASCII16X를 직접 고를 때는 지금도 이 규칙) 8MB로 채웠다(22a8a85). Yamanooto 파일은 그 자리가 FFh
  (서명을 넣으면 auto가 ASCII16-X로 잘못 고름): 섹터 12960개 중 중복을 뺀 8059개를 섹터마다 ZX0로 압축(안 줄면 원본), 3029KB.
  섹터 표(2바이트 배열 004000h + 1바이트 배열 00A600h: 8KB 뱅크, 뱅크 안 오프셋, 원본 여부)로 찾아 읽을 때 푼다.
  압축기: ZX0 v2.2 참조판(zx0/src, BSD-3, mkcart가 cc로 빌드), 압축 해제: dzx0_standard(68바이트, zx0/). 웹 도구에는 같은
  압축기의 JS 이식(8059개 섹터 모두 C와 바이트 일치). 시험 ROM: 섹터당 R800 2.0ms / Z80 11ms(원본 복사 0.7/3.3ms).
  배치: 000000h 부트, 004000h 표, 010000h 데이터(~310000h), 310000h 글꼴, 350000h 세이브 9×64KB, 3E0000h–3FFFFFh 빈 곳.
  세이브: 묶음 8개(24슬롯) + 예비 1섹터(공유). 헤더 'IC', 묶음, 세대. INIT이 헤더 9개로 묶음→섹터 표를 만든다(scan).
  저장 = 예비 섹터 지우기 → 묶음 복사(A0h 바이트 기록) + 새 슬롯 → 헤더 마지막, 이전 섹터가 예비가 된다.
  RAM 절약: 창 여닫을 때 페이지별 슬롯 대신 입장 때 A8을 저장·복원(카트리지는 외부 슬롯이라 RAM 확장 레지스터는 안 건드림),
  세이브 몸통(wslot/fetch/whdr/flget/scan)은 부트 ROM(페이지 1)에서 실행, 플래시 명령만 RAM.
  목적지가 페이지 1/2에 걸친 섹터는 창을 페이지 0(카트리지 거울)에 연다(지금까지 627건 중 0건).
  검증(openMSX, 두 매퍼): 진행 FM 125·MIDI 500·세이브 8 로드 125회 읽기 불일치 0, 표준 GT 글꼴 1068회 불일치 0,
  확장 슬롯 저장 → 재시작 16/16(유저 디스크 두 번, 디스크 1 한 번; 묶음이 예비로 옮겨가고 세대 비교 정상).
- `cart.asm` + `mkcart.py`로 4MB ROM 두 개(`ICITY_YAMA.rom`, `ICITY_A16X.rom`)가 나온다. **openMSX(kittya, 드라이브 비움)에서 부팅·진행 확인**:
  - 스타트 지점 → 디스크 2 → 미홍 대화 메뉴: FM 125회, MIDI 500회 읽기, 디스크 이미지와 **불일치 0** (두 매퍼).
  - 유저 디스크 세이브 7·8 로드 → 디스크 4·6 진입(2MB 넘는 뱅크, Yamanooto OFFR 경로): 114·125회, 불일치 0 (두 매퍼).
  - 슬롯 확장기 뒤(1-0)에 꽂은 경우(페이지 0 도우미 경로): 125회, 불일치 0.
- **패치 G2(2026-10-01):** 디스크 1 파일 14(엔딩 인트로, 커널 모드 2)의 한자 ROM 읽기 사본(ADFEh)도 `CALL E947h`로 돌리고 D500h의 글리프를 86BCh로 복사한다(`mkcart.py` G2_*).
  표준 GT에서 메인 메뉴 중 (0081)=2, PC=E000h로 강제 진입: 두 매퍼 모두 529회 호출이 KANJI.rom과 일치, 포트 쓰기 0(G2 없는 ROM은 572회). 세이브 영역(350000h–)과 글꼴(310000h)은 그대로라
  옛 ROM이 저장한 세이브를 새 ROM이 읽는다(save2.tcl 16/16, 두 매퍼). 바뀌는 곳은 000000h–30FFFFh. 실기 카트리지를 ROM 전체로 다시 쓰면 세이브도 지워지므로 백업하거나 앞부분만 쓸 것.
- **세이브 슬롯 확장: 디스크마다 96개(12페이지), 디스크 1 + 유저 디스크 = 192개.** 게임의 슬롯 목록에서 좌우 키로 8개씩
  페이지 전환(번호 9, 10 …으로 표시). 키보드 ←/→ 또는 조이스틱 포트 1·2의 좌우(MiSTer 게임패드): 콜백 `cbk`가 키보드 행 8과
  PSG R14(R15 bit 6으로 포트 선택, R15는 되돌림)를 함께 읽는다(`joy` X1 영역, `joyrd` DF67h, `wr15` F32Fh; openMSX에서 R14를 강제로 바꿔 페이지 2 저장·재시작 16/16, 두 매퍼). 파일 9 패치 P1–P6(mkcart `ui_patches`): 590Ah 메뉴 콜백(308Ah가 매 반복 HL로 부름),
  5957h 표시 번호, 5910h 선택 번호, 58E3h 목록 열 때(SRAM이면 0페이지), 5A66h/5A8Fh 섹터 계산(슬롯 9번부터 0600h+2n,
  디스크 밖). SRAM·Quick은 원본 그대로(8개/1개). 한 페이지 다시 그리는 데 약 5초(원본 목록 출력 속도 그대로).
  플래시: 슬롯 24개 = 64KB 섹터 한 쌍(8쌍, 6B0000h–7AFFFFh). 슬롯 p는 16KB 뱅크 p/8의 앞 8KB 안 (p mod 8)×1KB
  (ASCII16-X는 창 뒤 8KB에 쓰면 뱅크 레지스터가 바뀜), 헤더 'IC'+세대(16비트) +C000h, 유효하고 새 것이 현재.
  저장: 예비 섹터 지우기 → 24슬롯을 바이트 기록(A0h, FFh 건너뜀)으로 옮기며 새 슬롯 넣기 → 헤더 마지막. openMSX 약 2.2–2.7초.
  (처음엔 write-buffer 기록(25h…29h)이었는데 MiSTer MSX 코어의 플래시 FSM이 A0h와 섹터 지우기만 지원해 세이브가 안 됐다 — 바이트 기록으로 바꿈.)
  시험(`test/save2.tcl`): 유저 디스크 9번 저장 → 재시작 16/16, 같은 묶음 10번 → 섹터 반대로 넘어가 16/16(세대 2→3),
  디스크 1 9번 → 16/16, 두 매퍼 모두. 구현 중 버그: `savslot`의 `CP 9`가 디스크 1에서 CF를 남겨 세이브가 무시되던 것 수정.
- **세이브(30h)는 카트리지 플래시에 기록**: 디스크 1·유저 디스크의 슬롯 16개가 각각 64KB 플래시 섹터(6B0000h~)에 있다.
  주입 시험(로드 목록의 슬롯 2 읽기를 쓰기로 바꿈, `test/save.tcl`): 두 매퍼 모두 A=0, 약 1초. openMSX를 끄고 다시 켠 뒤
  슬롯 2 = 슬롯 1, 나머지 7개 불변, 플래시 전체에서 바뀐 곳은 그 슬롯 1KB뿐. 게임 안 세이브 화면(터미널)으로 하는 저장은 미확인.
  게임 자체의 Quick/SRAM 세이브는 원본 기능 그대로 둔다.
- **한글 글꼴은 항상 카트리지 안의 FONT.BIN**(G1 패치): 표준 GT(`Panasonic_FS-A1GT`, 한글 ROM 없음)에서 400초 동안
  글리프 1068회(141종)를 글꼴 파일과 32바이트 단위 비교 **불일치 0**, 한자 ROM 포트(D8–DBh) 쓰기 0회(두 매퍼).
  같은 기계에서 유저 디스크 세이브 8 로드 → 디스크 6: 125회 읽기 불일치 0.
- 실기 미확인.

웹 도구(`hdtool/webapp/icity_dsk_maker.html`)의 "만들 것 = 카트리지 ROM"도 같은 ROM을 만든다(바이트 일치, `test_cart.js`).
`cart.asm`/`mkcart.py`를 고치면 `webapp/make_cart_assets.py` → `build_app.py`로 페이지를 다시 만들 것.
빌드: `python3 mkcart.py <디스크 8장 폴더 또는 5.9MB 합본> <유저디스크.dsk> <FONT.BIN> [출력 폴더]` (글꼴: 저장소 루트 `KANJI.rom`, 262144바이트)
(`sjasmplus`는 같은 폴더의 것을 쓴다). 시험: `test/verify.tcl` 머리말 참고.

**참고 — 디스크 이미지 판본:** 저장소 밖의 `I-CITY_K.DSK`(합본)는 zip 원본과 디스크 1 섹터 66h 두 바이트가 다르다
(글꼴 루틴 file7 2AB9h의 포트 D9h/DBh → 59h/5Bh). G1 패치가 이 루틴을 통째로 바꾸므로 **어느 판으로 빌드해도 같은 ROM**이 나온다.
(G1 없이 59h 판을 GT에서 돌리면 글자가 흰 사각형.)

## 1. 설계 (확정·구현)
처음 안(H.PHYD로 디스크 ROM이 DOS1 환경을 만들게 하기)은 **폐기**했다(2절). 지금 방식:

1. **카트리지 INIT(4.9초)에서 기계를 넘겨받고 돌아가지 않는다.** 디스크 ROM 초기화·부트 섹터 모두 쓰지 않는다.
   슬롯 0(BIOS, MSX-MUSIC)은 슬롯 1보다 먼저 초기화되므로 필요한 것은 이미 되어 있다.
2. INIT이 원본 부트 섹터가 `JP 0100` 직전에 만드는 상태를 재현한다: 모든 페이지 RAM(A8=FFh, 확장 레지스터 00h),
   매퍼 FC–FF=3,2,1,0, SP=FAF8h, 0080h–0087h=`00 00 00 98 98 23 F3 00`, RAMAD0–3(F341h–F344h)=RAM 슬롯,
   HIMEM=DF7Eh, F368h/F36Bh/F36Eh=RET, FRAY.DOS(디스크 1의 파일, 0CA2h바이트)를 0100h에.
3. **자체 슬롯 환경**(원본 DOS1 환경 대신, 새로 작성):
   - 페이지 0 RAM: 000Ch RDSLT, 0014h WRSLT, 001Ch CALSLT, 0024h ENASLT, 0030h CALLF, 0038h 인터럽트,
     003Bh~ 확장 슬롯 레지스터 도우미(페이지 3를 다른 기본 슬롯으로 잠깐 바꿔 FFFFh를 쓰는 코드는 페이지 0에 있어야 함).
   - 페이지 3 DD92h–(322바이트, 한도 DF7Dh): 위 루틴 본체. 인터럽트는 원본처럼 DD92h 아래 자체 스택에서 BIOS 0038h를 CALSLT.
4. **F37D 처리기**: 페이지 3 **EF80h–F139h**(353바이트). 원본에서 이 자리는 DOS1 디스크 드라이버의 페이지 3 코드이고
   섹터를 읽을 때마다 실행되므로(측정) 게임이 절대 쓰지 않는 곳이다. 1Ah=DTA 저장, 2Fh=읽기
   (섹터 0이면 (5EC0h)로 디스크 전환, `hdtool/hook.asm`과 같은 규칙), 그 밖(30h 포함)은 A=0.
   읽기: ROM 섹터 = 80h + (디스크−1)×1440 + 섹터, 목적지 페이지 경계에서 나눠 복사. 창은 페이지 2(목적지가 페이지 2면 페이지 1),
   원래 슬롯은 EXPTBL/SLTTBL로 구해 복원.
   - Yamanooto: 8KB 뱅크 = 원시값 + 4×OFFR. OFFR(7FFEh, ENAR=01h일 때)는 페이지 1에서만 보이므로 카트리지를 잠깐 페이지 1에 올려 쓴다.
     원시값을 0–3으로 두어 9800h–9FFFh가 SCC로 바뀌지 않게 한다.
   - ASCII16-X: 16KB 뱅크(12비트 = 주소 bit8–11 + 데이터), 페이지 2 창은 B000h–BFFFh 미러로 설정.
5. INIT은 첫 줄에서 SP=DD92h로 옮긴다: BIOS 스택(F08Eh 근처)이 상주부 자리 안이라 덮으면 자기 스택을 망가뜨린다(실제로 겪음).
6. ROM 배치(두 매퍼 같음): 000000h 부트 16KB, 010000h 디스크 1–8 + 유저 디스크(9×720KB) ~664000h, 664000h 글꼴 256KB,
   6B0000h 세이브 8묶음×128KB(~7B0000h), 나머지 FFh. 플래시는 두 칩 모두 앞 64KB만 8KB 섹터, 그 뒤 64KB 섹터.
8. 세이브: 게임의 쓰기는 한 곳(`LD HL,0578h+2n / LD DE,F400h / LD C,30h / LD B,2`), 항상 슬롯 하나 2섹터(짝수 먼저).
   savslot/romsec이 디스크 1·유저 디스크의 슬롯 섹터를 묶음 배치로 돌리고(읽기·쓰기 공통), 현재 섹터는 헤더로 판정해 curg에 캐시.
   Yamanooto는 ENAR=10h(WREN) 동안만 기록(페이지 1에서 설정). 코드 배치: DD92h(env+wrabs+fmap/erase64/prog32),
   EF80h(상주부+funmap/chsec/possec/flget), E947h(글꼴+unlock/fcmd/fwait/wren/allff), F176h(목록 페이지+savslot/grp/curgp),
   F27Fh(romsec/curof/rdhdr), F13Ah(버퍼), F325h(변수/hdrsec/pairde), 페이지 0 0055h(fetch)·0090h(wslot).
   모두 거의 꽉 참(영역마다 ASSERT).
7. 글꼴: mkcart가 디스크 1의 G1(file7 2AB9h, 28바이트)을 `JP E947h`로 바꾼다. E947h(게임이 안 쓰는 E947h–E9FFh, 70바이트) 래퍼가
   idx = (hi&7Fh)<<6 | (lo&3Fh)로 글꼴 섹터·오프셋을 구해 상주부의 복사 루틴(xfer)으로 32바이트를 D500h에 넣고
   HL=D520h, BC=00D9h, DE·인터럽트 상태 유지로 돌아간다. 캐시 없음(ROM 직접).

## 2. 확인된 사실 (측정)
- **H.PHYD 경로가 안 되는 이유:** GT의 DOS2 커널은 9.0초에 드라이버 DSKIO를 **직접** 불러 섹터 0을 읽고, DOS1 부트 섹터일 때만
  DOS1 모드로 바꿔 PHYDIO(→H.PHYD)로 다시 읽는다. 빈 드라이브면 첫 읽기가 실패해 BASIC으로 간다. 또 디스크 ROM은
  59CEh에서 H.STKE가 C9h가 아니면 디스크 부팅을 건너뛰고, 9.8초에 훅 표(5C96h)를 다시 써 H.PHYD를 덮는다.
- 게임이 기대는 것(원본 60초, 게임 코드 PC만): 페이지 0 진입점 000Ch/0014h/001Ch/0024h/0030h/0038h, BDOS 1Ah/2Fh,
  RAMAD, EXPTBL. 게임은 페이지 0 전체를 다른 곳으로 복사한다(PC=8121h). H.KEYI는 게임이 직접 `JP E6C0`으로 건다.
  0005h는 게임이 스스로 `JP F37D`를 써 넣는다.
- 원본 `JP 0100` 때 디스크 ROM 훅(BASIC 디스크 명령, H.TIMI 모터 타이머)은 게임과 무관.
- 부팅 중(디스크 ROM 동작 중)에는 E947h–E9FFh를 디스크 ROM 쪽이 전부 쓴다(게임만 안 쓰는 곳).
- FRAY.DOS는 E000h부터 자기 코드를 복사한다(게임 페이지 3 코드 E000h–E946h, DTA EA00h).
- 메뉴 입력은 커서가 보인 뒤에만 받는다: 음원 메뉴 ≈40초, 메인 메뉴 ≈74초, 로드 메뉴 ≈94초, 로드 슬롯 목록 ≈126초(카트리지판 기준).
- 로드 메뉴: Quick / **SRAM** / 디스크 1 / 유저 디스크. 유저 디스크 슬롯 7(사이쿤지구)→디스크 4, 슬롯 8(토로지구)→디스크 6. (장소 이름은 웹 도구의 슬롯 목록과 같은 방식으로 게임 자료에서 푼 것)

## 3. 남은 일 (순서대로)
1. 실기 확인(Yamanooto, ASCII16-X): 부팅, 진행, 세이브 후 전원 껐다 켜서 로드. Yamanooto 실기는 자체 부팅 메뉴가 있을 수 있음.
2. 게임 안 세이브 화면(천인의 아파트 터미널)으로 실제 저장해 보기(지금은 주입 시험만).
3. 긴 진행(엔딩까지)에서 페이지 3 DD92h–DF7Dh·E947h–E9FFh·EF80h–F139h를 게임이 쓰지 않는지 쓰기 감시로 확인.

## 4. 파일
- `cart.asm`, `mkcart.py`, `test/verify.tcl`(매 읽기를 디스크 이미지와 비교 + 스크린샷), `test/font.tcl`(글리프를 글꼴 파일과 비교, 한자 ROM 포트 감시), `test/save.tcl`(세이브 쓰기 주입 → 재시작 확인).
  verify.tcl의 IMG는 G1이 들어간 디스크 1이어야 하므로 ROM의 010000h–663FFFh를 잘라 쓰는 것이 간단하다.
- `probe.asm`: INIT에서 H.STKE/H.RUNC를 거는 시험 ROM(부팅 시점 확인용, 1차).
- 헤드리스 스크린샷: `SDL_VIDEODRIVER=offscreen` + `set renderer SDLGL-PP`.
- 참고: `hdtool/hook.asm`(디스크 전환 규칙), `hdtool/mkdos2/patches.py`(G1), `hdtool/PLAN_BINPATCH.md`(세이브 구간·30h).
