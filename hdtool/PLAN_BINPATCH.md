# MSX-DOS2판 바이너리 패치 구현 계획 (branch: msxdos2)

`PLAN_MSXDOS2.md`의 설계를 0단계 조사 결과(`phase0/PHASE0_FINDINGS.md` §9–§13)에 맞춰 구체화한 것이다.
패치 주소와 바이트는 디스크 1의 `FRAY.DOS`(섹터 14–20, 0CA2h바이트)와 파일 13(섹터 228–237) 기준이다.

## 0. 결정 사항

| 항목 | 결정 | 근거 |
|---|---|---|
| 1차 목표 | **FM 전용**(E8F5=10h). 게임이 논리 세그먼트 00–0Fh만 쓴다 | §11-2, 필요 17개 ≤ 빈 21개 |
| 2차 목표 | MIDI: file13 모듈 패치로 곡을 필요할 때 파일에서 읽음(E8F5=13h) | §13-5, 필요 20개 |
| 게임 쪽 패치 적용 시점 | **변환 도구 `mkdos2.py`가 조각 파일(`D1_xxxx.DAT`)에 미리 적용** | 런처를 단순하게 유지. 원본 바이트 검증 후 적용 |
| 실행 시점 값(E8F5, 세그먼트 표) | 런처가 FRAY.DOS를 올린 뒤 정해진 주소에 써 넣음 | 할당 결과에 따라 달라짐 |
| 매퍼 전환 지점 | 커널 E25B 한 곳만 패치. 논리→물리 표 참조 | §1, §7–§9: 모든 매퍼 쓰기가 E2A7 한 곳 |
| 세그먼트 확보 | `ALL_SEG`(사용자 세그먼트)만 사용. R800 ROM 모드의 +4는 쓰지 않음 | FM 17, MIDI 20 모두 21개 안 |
| 데이터 이동 | 바운스 버퍼 없음. 게임 목적지의 **물리 세그먼트를 DOS2 환경 page 2에 올려 직접 읽고 쓴다** | 복사 한 번 절약, 스텁 코드 최소화 |
| 종료 | 리셋(원본과 같음). DOS2로 돌아가지 않는다 | 게임이 page 3·0을 다 쓰므로 복귀 가치 없음 |

## 1. 메모리 배치

### 1-1. 물리 세그먼트

런처가 `ALL_SEG`(B=0, 사용자 세그먼트)로 N+0개를 받는다. N = 논리 세그먼트 수(FM 16, MIDI 19).

| 논리(게임) | 물리 | 내용 |
|---|---|---|
| 00 | P0 | 게임 page 3. DOS2 환경 page 3(C000–FFFF) 사본으로 초기화한 뒤 F37D를 스텁으로 돌린다 |
| 01 | P1 | 게임 page 2 초기값 |
| 02 | P2 | 게임 page 1 초기값 |
| 03 | P3 | 게임 page 0. DOS2 page 0의 0000–00FF 사본(RDSLT/WRSLT/CALSLT/ENASLT 진입점 포함) + 스텁 |
| 04–0F | P4–P15 | 게임 데이터 |
| 10–12 | P16–P18 | MIDI 판에서만: 캐시 모듈(10h), 플레이어(12h), 11h |

DOS2 환경은 그대로 00/03/02/01(page 3/0/1/2)을 쓴다. 런처(TPA)는 **0100–7FFF 안에 둔다**. page 2(8000–BFFF)는 게임 세그먼트를 올리는 창으로 비워 둔다.

논리→물리 표 `TBL`(32바이트, 미사용 항목은 P1로 채움)은 게임 환경에서 E25B가 읽는다. 위치는 §8-1에서 정한다.

### 1-2. page 0 스텁 (두 환경의 page 0에 같은 바이트)

DOS2 page 0(물리 03)과 게임 page 0(P3)의 **0090h–00FFh에 같은 코드**를 둔다. page 0을 바꾸는 순간에도 실행 중인 바이트가 같아야 하기 때문이다.
게임은 0080–008Fh와 00A7h를 쓴다(§8-1에서 재확인). 스텁 변수는 게임 환경 page 0에만 있으면 되고, DOS2 쪽에는 레지스터로 넘긴다.

```
0090 enter:  DI
             LD (gsp),SP            ; 게임 SP 저장 (게임 page 0 변수)
             ; C=기능, DE=섹터, H=개수, L=드라이브 는 그대로 둔다
             LD IX,(dta)            ; 마지막 1Ah 로 받은 목적지
             LD A,03h : OUT (FCh),A ; ← 여기부터 DOS2 page 0. 바이트가 같으므로 계속 실행
             LD A,02h : OUT (FDh),A
             LD A,01h : OUT (FEh),A
             XOR A    : OUT (FFh),A
             LD SP,DOS2_STACK       ; 런처 안 고정 주소
             JP dos2_service        ; 런처(page 1) 코드
00xx leave:  DI                     ; dos2_service 가 A=결과, 물리 4바이트(BC'DE')를 들고 옴
             (물리 P0→FF, P2→FD, P1→FE 순서로 OUT, 마지막에 P3→FC)
             LD SP,(gsp)
             EI 여부는 진입 때 저장한 IFF 로 복원   ; §3-3
             RET                    ; F37D 를 CALL 한 게임 코드로
```

게임 환경 page 0의 0038h는 로더가 017Fh에서 `JP E6CD`로 바꾸기 전까지 DOS2 page 0 사본(DOS2 인터럽트 처리)이 남는다. 그 사이에 EI가 걸릴 수 있으므로(모듈 401Eh 등) **런처가 사본의 0038h를 `EI; RETI`류 최소 처리기(S#0 읽기 포함)로 바꿔 둔다.**

## 2. 게임 쪽 바이너리 패치 표

주소는 메모리 주소, 파일 오프셋은 `주소 − 0100h`(FRAY.DOS) / `주소 − 4000h`(file13). `mkdos2.py`가 원본 바이트를 확인한 뒤 바꾼다.

### 2-1. FRAY.DOS 로더 (0100–045A)

| # | 주소 | 원본 | 변경 | 목적 |
|---|---|---|---|---|
| L1 | 0111 | `CD 5B 03` CALL 035B | `CD xx xx` CALL `init_map` (부록 코드) | 매퍼 계수 루틴 우회. 035B는 모든 세그먼트의 8000h에 AA/55를 써서 DOS2 세그먼트를 부순다(041C). `init_map`은 039C–03AB(E8EB 표 초기화)와 같은 일을 하고 E8F3=20h, A=N을 돌려준다 |
| L2 | 011B | `3E 10` | 유지 | 모듈은 논리 10h에 그대로 |
| L3 | 01B3 | `3E 03 D3 F5` OUT (F5),3 | 유지 | 한자 ROM 제어. DOS2 환경에 영향 없음(확인 항목 §8-4) |
| L4 | 01F2 | `3E 81` CHGCPU 81h | 유지 | R800 ROM 모드. §8-3 |

`init_map`은 FRAY.DOS 끝(0DA2h 이후)에 붙인다(Nextor판 `hook.asm`과 같은 방식). FRAY.DOS는 런처가 파일에서 읽어 올리므로 길이 제한이 없다.
E8F3=20h로 두면 E25B의 `A < (E8F3)` 검사가 항상 참이 되어 **슬롯 전환(ENASLT) 경로가 절대 실행되지 않는다.**

### 2-2. FRAY.DOS 커널 (E000–E946)

| # | 주소 | 원본 | 변경 | 목적 |
|---|---|---|---|---|
| K1 | E266–E275 (16바이트) | `5F 3A F3 E8 57 7B 92 57 3E 83 38 04 5A 3A F4 E8` | `E5 21 lo hi 85 6F 5E E1 3E 83` + `00`×6 | 논리→물리 변환. `PUSH HL; LD HL,TBL; ADD A,L; LD L,A; LD E,(HL); POP HL; LD A,83h`. TBL은 256바이트 경계를 넘지 않게 둔다 |
| K2 | E60B–E612 | `3A F5 E8 FE 11 DA 7D F3` | `C3 7D F3` + NOP×5 | **MIDI 판만.** 디스크 읽기 래퍼가 섹터 캐시(모듈 400Ch)를 거치지 않고 바로 F37D로 가게 한다. 캐시 크기 0일 때 028Fh 검색 루프가 65536회 도는 것을 피한다(§13-3) |

K1 뒤의 원본 흐름: E276 `CP (HL)`이 83h와 E8EB 표의 슬롯 바이트(039C에서 (F344)=83h로 초기화, init_map도 83h로)를 비교해 같으므로 E29F로 가서 `EI; OUT (C),E`. 즉 **DI/EI 동작과 OUT 경로는 원본 그대로**다.

### 2-3. file13 모듈 (MIDI 판만)

| # | 주소 | 원본 | 변경 | 목적 |
|---|---|---|---|---|
| M1 | 4145 (루프 시작) | `2A 2E 43 CD 8C 42 …` | 섹터를 읽지 않고 (432E)를 (4387)만큼 늘리고 (4387)=0 | 곡 미리 읽기 제거. 4333h 표(곡 시작 인덱스)는 원본과 같은 값이 된다 |
| M2 | 42E9 | 캐시 인덱스→세그먼트 변환 후 F400h로 512바이트 LDIR | (432E) 인덱스를 섹터로 바꿔 F37D(2Fh, 1섹터, DTA=F400h)로 읽음. 섹터 = 0152h + (인덱스 − 0250h). 인덱스 증가는 유지 | 곡 데이터를 파일에서 직접 읽기 |
| M3 | 40AC–40B3 / 4098–409B | 초기화용 첫 항목(014Ah 8섹터) 읽기 | 초기화 때는 42E9가 014Ah부터 읽도록 별도 기준 섹터를 쓴다(예: (4385)를 기준으로 삼는 플래그) | §13-5 2번의 미결 사항 |
| M4 | 4113–4136, 4242–4264 | 섹터 캐시 크기 계산 | (432C)=0 | K2로 경로를 끊었으므로 안전장치 |

M2의 F37D 호출은 곧 우리 스텁 호출이다. 세그먼트 12h가 page 0, 11h가 page 2에 올라간 상태에서 부르므로 스텁이 page 0에 있어야 한다는 조건은 이미 만족한다(스텁은 모든 게임 page 0 세그먼트에 있어야 함 → **page 0에 올라갈 수 있는 논리 세그먼트 03, 05, 12h의 물리 세그먼트에도 스텁 사본을 둔다**. §7 실측: page 0에는 03, 05, 12h만 올라온다).

## 3. F37D 요청 처리 (DOS2 환경, 런처 코드)

### 3-1. 기능
| C | 처리 |
|---|---|
| 1Ah | DE를 게임 page 0의 `dta`에 저장하고 돌아간다(환경 전환 없음) |
| 2Fh | 절대 섹터 읽기. L=0(A:) 만 지원. DE=섹터, H=개수 |
| 30h | 절대 섹터 쓰기. 세이브 구간(0578h–0587h)만 허용, 그 밖은 오류 |
| 그 외 | 디버그 빌드: 화면에 C와 복귀 주소를 찍고 멈춤. §8-2에서 실제 사용 집합을 확정한 뒤 최종 판단 |

### 3-2. 2Fh 처리 순서
1. 스텁에서 넘어온 DTA, 섹터, 개수를 받는다.
2. 섹터 0이면 (5EC0h) — 게임 page 1에 올라온 file9의 변수 — 를 읽어 원하는 디스크를 정한다(0–7→디스크 1–8, 10→유저). 이 값은 논리 세그먼트가 아니라 **현재 page 1의 물리 세그먼트**(E8EB 표에서 논리 번호를 읽어 TBL로 변환)를 DOS2 page 2에 올려 읽는다.
3. 요청 구간을 조각 표에서 찾아 `(파일, 오프셋)` 목록으로 만든다. 조각 경계에서 나눈다.
4. 목적지 구간을 16KB page 경계에서 나눈다. 각 조각의 물리 세그먼트 = TBL[E8EB[page]] (E8EB는 게임 page 3 = P0을 DOS2 page 2에 올려 읽음: A8EBh).
5. 조각마다 `PUT_P2`(매퍼 지원 루틴)로 물리 세그먼트를 DOS2 page 2에 올리고 `_SEEK` + `_READ`를 8000h+오프셋으로 부른다. 끝나면 `PUT_P2`로 원래 01h를 되돌린다. **OUT 직접 쓰기 금지** — DOS2가 자기 그림자 값으로 page 2를 되돌릴 수 있다.
6. 결과 A(0=성공)를 들고 `leave`로 간다.

### 3-3. 전환 중 상태
| 항목 | 처리 |
|---|---|
| 인터럽트 | 스텁 진입 때 IFF를 `LD A,I`(P/V)로 저장. DOS2 환경에서는 EI 허용(DOS2 0038). 복귀 때 복원 |
| VDP R15 | DOS2 환경 EI 전에 R15=0(BIOS 인터럽트가 S#0을 읽음). 복귀 때 복원할 값이 없으므로 게임이 R15≠0을 유지한 채 F37D를 부르는지 §8-5에서 확인 |
| PSG/FM | BIOS 인터럽트가 PSG 레지스터 14를 읽는다(주소 레지스터 변경). 게임 드라이버가 매번 주소를 다시 쓰는지 확인 항목 |
| CPU | 게임이 R800 ROM 모드로 바꾼 상태에서 DOS2·드라이버를 부른다. §8-3 |
| 스택 | DOS2 스택은 런처 안 고정 영역(512바이트) |

### 3-4. 파일과 조각
- 조각 이름 `\ICITY\D<n>\D<n>_<시작섹터 4자리 hex>.DAT`, 유저 디스크는 `\ICITY\DU\`.
- 세이브 구간은 디스크 1과 유저 디스크의 0578h–0587h(16섹터)를 별도 조각으로 잘라 `\ICITY\SAVE\D1_0578.DAT`, `DU_0578.DAT`에 두고 읽기·쓰기로 연다.
- 섹터 0은 각 디스크 조각 파일의 첫 섹터에 그대로 있다. 라벨 합성은 필요 없다.
- 파일 핸들은 디스크별로 마지막 하나를 열어 두고 같은 파일이면 재사용한다.
- 조각 표(디스크별 시작 섹터 정렬 목록)는 `mkdos2.py`가 `chunks.inc`로 내보내고 런처가 포함한다.

## 4. 런처 `ICITY.COM` 흐름

1. `_DOSVER`로 DOS2 ≥ 2.20 확인. EXTBIO(D=4,E=2)로 매퍼 지원 루틴 표. 빈 세그먼트 수를 화면에 표시(실기 측정 겸용).
2. `ALL_SEG`×N. 부족하면 필요 수와 함께 종료. 실패 시 이미 받은 것은 종료 때 자동 반환.
3. TBL을 만들고 런처 안 사본과 게임 쪽(§8-1 위치)에 쓴다.
4. 게임 page 3(P0) 준비: DOS2 page 3 전체를 P0에 복사(PUT_P2로 P0을 page 2에 올리고 C000→8000 LDIR), P0의 F37D에 `JP 0090`.
5. 게임 page 0(P3) 준비: DOS2 0000–00FF 복사, 0038 임시 처리기, 스텁 0090–00FF. 스텁 사본을 P5, P18(page 0에 올라올 논리 05, 12h)의 0090–00FFh에도 둔다.
6. FRAY.DOS를 조각에서 읽어 P3의 0100h(=page 2 창의 8100h)에 올리고 실행 시점 값을 쓴다: `init_map`의 A=N, TBL 내용.
7. 진입: DI, 매퍼 P0/P1/P2/P3, SP=F380h 부근(로더가 E086에서 FAF8로 바꿈), `JP 0100`.

## 5. `mkdos2.py`

입력: 원본 dsk 8장 + 유저 dsk. 출력: 조각 파일 트리, `chunks.inc`, 검증 보고.
1. 구간 좌표 수집(§3 확정 목록): 섹터 11 파일 표, INF 이름 레코드와 꼬리, 엔진 표(디스크1 파일7 0539h 12쌍, 파일9 EA00 인덱스), 고정 구간(0, 0578h+2n). 파일 14 참조 여부는 워드 스캔으로 확인.
2. 모든 시작·끝을 분할점으로 조각을 만들고, 어느 구간에도 안 속하는 0이 아닌 섹터는 별도 조각.
3. 패치 적용(§2). 원본 바이트 불일치면 중단.
4. 조각을 다시 이어 붙여 **패치 지점 외**가 원본과 바이트 단위로 같은지 확인.
5. 디스크당 조각 수를 보고. 200개를 넘으면 인접 조각 병합 옵션.

| 요청 동일성 | 원본(플로피)과 DOS2판에서 같은 세이브로 같은 구간을 돌며 F37D 요청 목록과 목적지 메모리 CRC 비교 | 일치 |
| 진행 | 타이틀→스타트→디스크 2, 세이브 8개로 디스크 4–8, 세이브·로드 | 원본과 같은 화면 |
| MIDI | 곡 전환 시간 측정(F37D 요청 수×시간), 곡 정상 재생 | 체감 기준은 사용자 판단 |
| 환경 | `kittya`+`ide`(ASCII DOS2 2.31 + Sunrise IDE 2.50), `kittya`+MFRSD(Nextor 2.1.2) 둘 다 | 둘 다 통과 |
| 실기 | FS-A1GT + MMC/SD V4 | 위 진행 항목 반복 |

## 7. 작업 순서

| 마일스톤 | 내용 | 완료 기준 |
|---|---|---|
| M0 | §8 미결 사항 확인(모두 openMSX 스크립트) | 표 위치·기능 집합 확정 |
| M1 | `mkdos2.py`: 조각 분할 + 검증(패치 없이) | 원본 재조립 일치 |
| M2 | 런처 골격: 검사·할당·표시, 세그먼트 준비, 스텁, FRAY.DOS 로드, 로더 패치 L1 | 로더가 E015(섹터 11 읽기)까지 가서 스텁을 부른다 |
| M3 | 2Fh 처리 + 조각 해석 + K1 | 타이틀 화면 |
| M4 | 30h + 세이브 파일, 섹터 0 디스크 선택 | 디스크 1→2, 세이브·로드 |
| M5 | 두 에뮬 환경 전체 진행 + 세그먼트 보호 검증 | §6 통과 |
| M6 | MIDI: K2, M1–M4 패치, 곡 전환 시간 측정 | MIDI 정상 재생 |
| M7 | 실기 | 사용자 확인 |

## 8. 미결 사항과 확인 방법

### 8-1. TBL과 스텁 변수 위치 — 확인 완료(2026-09-29)
`phase0/watchfree/watchfree.tcl`로 E947h–E9FFh와 0090h–00FFh 쓰기를 감시했다. MIDI 시작→디스크 2(400초), FM 세이브로 디스크 7·6(각 300초) 동안 **쓰기 0회**(00A7h 포함).
결정: **TBL은 E960h**(32바이트, E960–E97F. 256바이트 경계 안), 스텁과 변수는 **0090h–00FFh**. E947–E95F는 예비로 비워 둔다.
남은 위험: 세이브 쓰기 경로와 엔딩은 아직 감시하지 않았다. M5 검증에서 같은 watchpoint를 켜 둔다.

### 8-2. 게임이 쓰는 BDOS 기능 집합 — 확인 완료(같은 실행)
게임 시작 뒤 F37D에 들어온 C는 **1Ah, 2Fh뿐**이었다(부팅 섹터가 FRAY.DOS를 올릴 때 쓰는 0Fh/27h/10h는 런처가 대신한다). 30h는 세이브 쓰기(정적 확인)이며 이번 실행에서는 세이브를 하지 않았다.
결정: 스텁은 1Ah/2Fh/30h만 처리하고 그 밖은 멈추고 알린다.

### 8-3. R800 ROM 모드에서 DOS2 + SD 드라이버
게임이 CHGCPU(81h) 뒤에 F37D를 부르므로 DOS2 커널과 MMC/SD V4 드라이버가 R800 ROM 모드에서 돈다. openMSX에서는 문제를 못 잡는다(드라이버가 다름). 실기 M7에서 확인. 문제가 나면 스텁에서 CHGCPU(80h)/(81h)를 요청마다 감싼다(BIOS 호출 비용).

### 8-4. 포트 F5(01B3)와 DOS2
게임이 OUT (F5),3을 한다(한자 ROM·시스템 제어). DOS2 커널이 F5를 다시 건드리는지, 한자 표시가 두 환경에서 같은지 확인.

### 8-5. VDP R15
F37D 진입 시점에 R15가 0이 아닌 경우가 있는지 openMSX `VDP regs` 디버거블로 기록.

### 8-6. 00A7h
로더 021Eh가 (00A7)에 쓴다(CHGCPU 실패 경로). 스텁 배치가 00A7을 피하는지 확인하고, 8-1 결과에 따라 스텁 시작을 00B0으로 옮긴다.

## 부록. `init_map` (FRAY.DOS 뒤에 붙임)

```
init_map:
        LD   HL,E8EBh           ; 039C–03AB 과 동일: (논리 3,2,1,0 / 슬롯 83h) × 4
        LD   B,3
.l:     LD   (HL),B : INC HL
        LD   (HL),83h : INC HL
        DEC  B
        JP   P,.l
        LD   A,20h
        LD   (E8F3h),A          ; 모든 논리 번호가 1차 매퍼 경로
        LD   A,N                ; 런처가 씀 (FM 10h, MIDI 13h)
        RET
```
